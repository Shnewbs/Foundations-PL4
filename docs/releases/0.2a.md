# Foundations PL4 0.2a — Network Storage and Component Selection

**Alpha release. Further API testing is still required.**

## Included in this build

Wireless Storage now aggregates accessible sided item inventories from Nodes and Transfer Nodes on its bound physical data network. The screen supports name/resource-ID search, name/quantity sorting, six item variants per page, withdrawals across matching sources, and offhand deposits that continue past full inventories. Item components remain separate variants. Visual-only reader links do not grant storage access.

Every action revalidates ownership, the held tool and its binding, loaded targets, topology, configuration, and directional filters. Single-use session tokens reject stale requests. Scans remain bounded to 256 endpoints and 4096 slots; no target chunk is force-loaded.

Receiver settings now offer searchable, paged emitter selection; Entity Nodes offer nearby living-entity selection. Arrays and supported components accept held transceiver links with server-side validation. Target types, applicable ownership, dimension policy, link limits, and duplicates are checked before saving. Entity links belong on Entity Nodes, not Arrays.

## Validation and release safety

The 1.21.1 source passed all 191 required native GameTests before version preparation, including eight new network-storage and component-link tests. The release pipeline repeats offline checks, native compilation, standalone-JAR checks, and the native GameTests against the final versioned source before publishing. Source snapshots and verification logs are retained as workflow artifacts.

Stale protocol and test-count guards have been corrected without removing validation. Version preparation aligns Gradle, the guide, README, payload metadata, and registered test counts; seven metadata-tool tests cover preflight failures and repeatability.

## Version targets

This release is the **Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21** build. Minecraft **26.1.2** and **26.3** have separate 0.2a branches and verified JARs. Install the JAR matching your Minecraft version.

## Local packaging verification (12 October 2026)

A clean Java 21 / NeoForge 21.1.250 build passed. The 191 GameTest fixtures compile in an isolated source set and load alongside PL4 in one development module; the production JAR gate rejects fixture classes and the test-only structure. All 191 required native GameTests passed on the final artifacts. The workflow now checks the server log explicitly because an earlier server crash returned a successful Gradle exit.

## Upgrade notes

Back up worlds before upgrading. Host save schema remains 2. Network payload protocol is now 5 because storage requests include search and sorting fields: client and server must both run matching 0.2a builds. Do not mix a 0.1b client with a 0.2a server. Existing reader/display bindings on Wireless Storage must be rebound to a Node or Transfer Node. Do not downgrade worlds containing newer configuration fields without a backup.

## Still pending

Installed optional-provider API testing, live multiplayer testing, in-game visual acceptance, and extended large-world testing remain pending. Passing native tests does not certify every external mod API or every modpack combination. Full Practical Logistics 2 parity is not claimed. This update does not add network fluid storage or turn read-only telemetry adapters into universal energy converters.
