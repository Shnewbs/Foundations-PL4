# 0.0.2a.R1.2 — Cable connection synchronization

- Reconcile nearby cable arms from received multipart contents on the client, instead of rendering independently received arm snapshots. Both ends update together once the new part is available.
- Refresh local geometry on client host load, data receipt, and removal, using the same multipart topology rules as the server. Blocked ports, cable families, face attachments and external leads remain respected.
- Replace six repeated server pair plans with one bounded local plan. A refresh inspects at most 25 cells and updates at most seven hosts; it never force-loads chunks or rebuilds global networks.
- No speculative client placement, faster cable tiers, sample-rate changes, save format changes or packet protocol changes.

Three native regressions cover stale arm snapshots in either arrival order, farther neighbour connections, blocked ports, cable family isolation, device leads, removal and global rebuild counts.

The reported R1 video shows temporary half-connections during placement. This patch addresses the asynchronous arm-snapshot path; visual acceptance in the user's modpack remains pending. It does not claim to eliminate server/network latency before a placed part is received.
