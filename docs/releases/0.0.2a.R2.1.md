# Foundations PL4 0.0.2a.R2.1 — reader finalization and correctness

- Searchable endpoint pages, 64 per page, and up to 64 saved per-reader names. Pinned target feedback remains correct outside the visible page or search.
- Server validates target selection against the current network, rather than a stale synchronized choice list. Spectators cannot send settings edits.
- Deduplicate repeated links, shared item/fluid handlers and vanilla combined chests, barrels and shulker inventories. Native 26.3 adapters expose their underlying provider identity for telemetry.
- Network Reader adds available/unloaded-or-missing counts and block/entity endpoint counts, respecting the configured row limit.
- Fix 26.3 furnace progress/fuel fields to use current Minecraft save keys; native acceptance uses a running furnace on both tracks.
- Provider registration handles are generation-specific: closing an old handle again cannot unregister a replacement callback. Immutable registry snapshots are refreshed only on registration changes. Off-thread sink writes are rejected.
- Removed dead imports, an unused diagnostic counter and redundant sampling conditions. Added regression cases for large-network selection, saved aliases, real double-chest totals, real furnace progress, provider lifecycle and diagnostics.

Validation scope: native Minecraft/NeoForge server suites plus offline/source/resource checks. Client visual inspection, two-player gameplay and actual installed optional power mods remain acceptance work; this release does not claim those passed or that arbitrary overlapping modded storage wrappers can be deduplicated safely.
